# Example configuration / 示例配置

These files are **examples, not defaults**. A project generated by `init_project.py`
never reads this directory; `config/project.yaml`, `config/analysis.yaml`,
`config/scheduler.yaml`, and `config/samples.tsv` are written from the intake you
supply. These examples exist so that a new project has one concrete, filled-in
instance of every field instead of a blank schema.

这两个文件是**示例，不是默认值**。生成的项目不会读取本目录；`config/` 下的四个配置
文件由你提供的 intake 写出。示例的作用是提供一个填好的完整实例，而不是空白模板。

## Files / 文件

| File | What it is | How to use it |
|---|---|---|
| `example-ipf-tissue.yaml` | A complete schema-v2 **intake**, the input format `init_project.py` accepts | `python scripts/init_project.py --intake config/examples/example-ipf-tissue.yaml --output /path/to/new-project` |
| `example-samples.tsv` | The same two sample rows in the **generated manifest** form (`config/samples.tsv` layout) | Reference, or copy over `config/samples.tsv` and edit |

## What this example is

A two-donor lung-tissue study with paired 10x RNA and per-cell indexed ALLC data.
It exercises every input class the skill supports: RNA-only, ALLC-only, and both
modalities on the same cells, with `cell_id_prefix` making the RNA barcodes and
the ALLC filenames resolve to the same cell IDs.

It is also the study the packaged stage scripts were originally developed
against, so the parameter values here are the ones that actually ran — not
invented placeholders. Treat them as a worked example of *what a decision looks
like when written down*, not as scientifically correct values for your data.

## Observed magnitudes / 观测到的量级

Recorded so a new project can sanity-check its own numbers at each stage. Every
figure below is from this one study; none of them is a target or a threshold.

| Quantity | Value | Where it is meaningful |
|---|---:|---|
| Input cells, CYL / ZCP | 4,264 / 4,685 | Before QC. Compare only against the same inputs. |
| Scanpy cells after QC + Scrublet | 8,696 | RNA route; drives the cluster structure |
| Leiden clusters | 18 (0–17) | A **structural change alarm**, not a label set |
| Cells with ALLC coverage ≥ 300k CpGs | 6,264 | Methylation route. This is *not* the Scanpy cell count. |
| Train / validation split | 5,638 / 626 | 90 / 10 of 6,264; CYL 2,638 + ZCP 3,000 train |
| Cell types with approved annotation | 14 | Required before cell-type DMR |

The 8,696 and 6,264 figures differ because the two routes select cells on
different evidence: RNA QC for Scanpy, per-cell CpG coverage for methylation.
A project that reports one number for both has conflated the two routes.

## What must be re-derived, never copied / 必须重新推导，不可照搬

1. **QC thresholds.** `min_genes`, `max_genes`, `min_counts`, and `max_mt_percent`
   are starting points to confirm against your own per-cohort distributions. The
   Scanpy notebook prints those distributions precisely so they can be challenged.
2. **Expected cell counts.** `SCMO_EXPECTED_CELLS` must come from the actual
   filtered cell list row count, not from a remembered number. A hardcoded count
   turns a real upstream change into a silent pass.
3. **Annotation.** `review_status: unreviewed` above is deliberate. Cell-type DMR
   and VMR+DMR stay blocked until a human approves the cluster-to-cell-type
   mapping, and `NA` / `Unassigned` labels are never usable for it.
4. **Cluster mappings.** A new cluster set is unreviewed by definition; numeric
   cluster labels are not transferable between runs.
5. **Scheduler policy.** The `scheduler` block is intentionally empty. Partitions,
   accounts, node allow/exclude lists, and per-profile resources describe *your*
   cluster. Copy them from your site, never from here.
6. **Input locations.** The `data.sources` paths stand in for the study's shared
   storage. Point them at where your own data already lives; `init_project.py`
   links each one into `Data/` rather than reading it in place, so the generated
   project stays reproducible from its own directory.
7. **Reference files.** `chrom_sizes` and `blacklist` are omitted above so the
   skill's bundled GRCh38 files fill them in. A project on another genome must
   declare its own; digests are recomputed and verified on every run.

## Site-specific values deliberately absent

Project roots, login and compute node names, shared filesystem paths, scheduler
accounts, and absolute interpreter paths appear **nowhere** in the packaged
scripts. They are supplied at runtime through `config/` and the environment. If
you find one hardcoded in a stage script, that is a defect — see
[template maintenance](../../../references/template-maintenance.md).
